旅游Agent

确定的workflow

首先明确时间 地点(多) 时间是否紧张

获得->
{
    "time":"4天",
    "start_day": "2026-08-03" | None
    "end_day": "2026-08-06" | None
    "location":{"宜兴","宣城"},
    "state":"relaxed"
    "budget":"3000"
    "others":"尽量不要在早上安排行程"
}
创建一条数据库存入数据库用于判断当前处于什么阶段
(目前仅个人使用不考虑用户字段 仅任务号 获取的属性内容)
=> 首先通过地点去小红书搜索相关帖子 (该部分要进行prompt扩写)
get tips_lists
循环处理每个帖子:
    => 首先判断该帖子是否是旅游相关
    如果是：<该部分存入数据库 内容可能较多考虑是否存入其他index中建立任务号关联>
    1.获取推荐的景点或旅游项目或推荐美食 + 相关的注意事项
    {
        "景点名/旅游项目/美食":"...<注意事项>"
        ...
    }
    2.总结该帖子 要求列出所有的景点或者旅游项目或推荐美食 + 对其总结
      {
        "景点名/旅游项目/美食":"...<总结>"
        ...
    }
    3.列出所有的景点或者旅游项目或推荐美食 + 预计的游玩时长
    4.列出所有的景点或者旅游项目或推荐美食 + 预计的消费
    可将其存入redis中按照地点和不同目的进行保存
    否则：
    continue

然后将以上信息给一个Agent做总结 带上要求之前的要求 对 景点 旅游项目 美食 做取舍

(将得到景点 旅游项目 美食 交给规划Agent 来安排时间 这里考虑接入天气MCP)  <该部分涉及到时间暂时不做存储>

    "第二天":
        "早上":"无安排",
        "中午":"xxx馆 吃...",
        "下午":{"xxx景点","xxx旅游项目"}
        "早上":"无安排"
}

将规划和循环处理得到的内容同时丢给总结Agent生成最终内容<内容存入数据库 并做向量化处理>
